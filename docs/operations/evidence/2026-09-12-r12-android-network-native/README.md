# Earlier Android Core6b network and native failure checks

Document class: EVIDENCE. [Exact original captures](receipt.json).

These checks preceded the f071 startup/numeric-build work. Installed client was
`2aa57015`, Core `6b271dec`, x86_64 APK `baa52029…`; they must not be relabeled as
2c370af installed proof. Only the owned LDPlayer14 index3 was used.

An owner-authorized ordinary admin action granted exactly one day of test access
to the owned account selected through case58 and its exact installation hash.
The entitlement's PAID/admin_grant labels are technical; no money or payment was
processed. Actual normal app Connect created tun0 and the running VPN service.
Ten HTTPS requests to the owned authenticated egress probe all returned204 with
the expected marker. Tunnel counters advanced rx37039/tx36580 bytes; these include
ambient traffic, not exclusively the probe. The protection details reported
confirmed tunnel, DNS and egress. Ordinary UI Disconnect removed the TUN/service.
Before/after owned HTTPS requests also passed. IPv4 route and all four DNS state
hashes matched. The raw IPv6 route hash differed; raw routes were not retained,
so semantic IPv6 restoration remains unproven and requires a new comparison.

The app-PID logcat available at readback was684 bytes with no matches in the six
reported privacy patterns and no FATAL/ANR. Its original scope string says
through the session, but the capture is only the available buffer; it does not
establish uninterrupted logging or absence from every sink.

A later, explicitly scoped rooted fixture injected six separate synthetic
invalid profiles (token/auth/cookie/URL/IP/provider), with valid staged profile
checksums, through the actual service restore path. Each reached a recorded
session_started/failed pair and created no TUN. Available app-PID logs and the
native journal contained none of the planted values; all three persisted
observability sinks also had zero matches. This is native failure privacy
proof, not proof that every value reached a GUI or delivered bundle.

The original rollback attempt exceeded Windows' command-line limit when it
tried to restore the live profile. Retained guest-private rollback copies were
then copied locally inside the guest, restoring both original byte hashes.
No live profile was exported. Both the initially executed source and corrected
cleanup helper are retained. Force-stop during restoration lost in-memory
native events, so the complete native-to-app bundle chain remains unproven.
Root config was disabled after shutdown; the later f071 installed capture
provides the actual rootless guest su127 check.

All recorded boots ended stopped, other instance disks were unchanged, and
sampled C/E free stayed above40GiB within the512MiB growth budget. This receipt
adds retained lineage; it does not close full V01/C05 or release gates.
